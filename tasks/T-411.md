## 任务描述
文件下载/上传目前走「整文件 base64 → 加密 JSON 信封」：`pullDeviceFile` 把设备文件读进内存后用
`sendProtectedBuffer`（`data: buffer.toString("base64")`）返回，`readProtectedBinaryBody` 反向 base64 解码。
下载 200 MB 文件会让内存出现 ~530 MB 峰值（原始 + base64 + JSON 字符串），并且上传侧同理（S-10）。

改为**二进制流式**：
1. 后端下载：`pullDeviceFile` 只做 adb pull 到临时文件并返回文件路径与文件名；路由用 `fs.createReadStream` 分块写响应，
   结束后删除临时文件（`close`/`error` 都要清理），响应头带 `Content-Disposition`、`Content-Type`、`Content-Length`。
2. 后端上传：`PUT /api/devices/:serial/files/upload?path=...` 直接把请求体流式写入临时文件（`stream.pipeline` + 大小上限），
   完成后 `adb push`，再删临时文件；不再要求 base64/加密信封。
3. 鉴权与错误语义保持：未登录仍 401；路径缺失 400；文件不存在 404；目录 400。错误响应仍用 JSON（可为明文 JSON，
   因为会带 session 校验）。
4. 前端：下载改为 `fetch` 拿 `response.blob()` 后 `URL.createObjectURL` 触发保存；上传改为 `fetch` 直接发 `File`（`body: file`）。
   UI 文案与进度提示保持现有行为。
